# 关键设计决策

本文记录 LifePilot v1.0.0 的主要工程取舍。它们服务于“个人本地 Agent + 可公开审阅的求职作品”这一目标，并不试图覆盖所有生产级场景。

## 1. 使用 LangGraph 管理 Agent 工作流

### 决策

使用显式 StateGraph，而不是只在一个函数中循环调用模型和工具。

### 原因

- 消息状态、工具节点和执行路径可以独立测试。
- Checkpointer 可以持久化 graph 状态。
- interrupt/resume 能表达需要用户确认的暂停点。
- recursion limit 可以为异常循环设置明确边界。

### 代价

LangGraph 状态、ToolMessage 顺序和恢复语义增加了实现复杂度。项目因此增加了不完整工具调用清理、Checkpoint 测试和审批恢复测试。

## 2. 将删除操作设计为 Human-in-the-loop

### 决策

删除待办、笔记、长期记忆和知识文档时，由工具触发 interrupt，收到明确批准后才继续。

### 原因

模型生成工具调用并不等同于用户已经授权不可逆操作。审批边界放在工具内部，可以保证无论调用来自普通 API、流式 API 还是 CLI，敏感动作都先触发同一中断规则；当前完整的批准/拒绝交互由 API 和 Streamlit 提供。

### 代价

客户端必须保存 thread ID，并实现 pending、approve、reject 和 resume 状态。中断期间的消息历史也需要保持合法的模型消息序列。

## 3. 区分短期会话状态、长期记忆和业务数据

### 决策

- LangGraph 消息和执行位置存入 Checkpoint 数据库。
- 用户资料及长期事实存入独立 Repository。
- 待办、笔记和会话索引作为业务数据保存。

### 原因

三类数据具有不同生命周期。模型对话历史不应自动成为永久用户事实；长期记忆必须通过明确工具调用写入；业务对象则需要稳定 CRUD 和查询接口。

### 代价

恢复完整本地状态时需要同时备份应用数据库和 Checkpoint 数据库。

## 4. 使用 SQLite 作为本地持久化方案

### 决策

应用数据和 Checkpoint 均使用 SQLite。

### 原因

- 无需独立数据库服务。
- 项目克隆后容易本地运行。
- 事务和约束能力足以支持本地多账号、单实例场景。
- 测试可以为每个用例创建临时数据库。

### 代价

不适合多实例并发写入和横向扩展。如果目标变成多人在线服务，应迁移到共享数据库，并重新设计锁、事务和迁移流程。

## 5. Repository 与 Agent Tool 分层

### 决策

Repository 处理 SQL 和领域数据，Tool 负责模型可理解的参数与文本结果。

### 原因

- 数据行为可以脱离模型进行确定性测试。
- API 或其他入口可以复用 Repository。
- Tool 不需要拼接 SQL，也不负责连接生命周期。
- owner 数据隔离集中在数据访问层验证。

### 代价

同一个业务动作需要跨越 Tool 和 Repository 两层，但换来了更清晰的职责和测试边界。

## 6. 使用本地 Embedding 和本地 Chroma

### 决策

文档向量化使用本地 `BAAI/bge-small-zh-v1.5`，向量存储使用持久化 Chroma。

### 原因

- 私人文档不必发送给远程 Embedding API。
- RAG 评估可以离线、可重复运行。
- 中文检索能力与个人资料场景匹配。
- 无额外向量服务依赖。

### 代价

首次运行需要额外下载模型，并占用本地存储和 CPU 内存。大规模文档和并发检索不属于当前设计范围。

## 7. Streamlit 只通过 FastAPI 访问业务能力

### 决策

Web UI 不直接导入 Repository 或调用 graph，而是使用统一 API Client。

### 原因

- 明确前后端边界。
- API 协议可以通过 MockTransport 测试。
- 认证、限流、错误格式和 Request ID 统一生效。
- 后续替换 UI 时不需要重写 Agent 后端。

### 代价

本地应用需要同时运行两个进程，且要处理流式协议和后端不可用状态。

## 8. 使用 SSE 提供流式响应

### 决策

聊天流式接口使用 Server-Sent Events，而不是 WebSocket。

### 原因

当前交互主要是客户端提交一次请求、服务端持续发送事件。SSE 与 HTTP、FastAPI StreamingResponse 和普通代理的组合更简单，也便于定义 token、approval、done 和 error 等事件。

### 代价

SSE 是单向流。如果未来需要客户端和服务端在同一连接上进行高频双向通信，应重新评估 WebSocket。

## 9. 只对模型客户端进行有限重试

### 决策

DeepSeek 客户端配置超时和有限重试，但不自动重放整个 Agent 请求。

### 原因

完整 Agent 工作流可能已经创建待办、写入笔记或更新记忆。对整段工作流无条件重试可能重复产生副作用。模型网络请求的有限重试风险更可控。

### 代价

部分瞬时故障仍会暴露给调用方，需要用户使用相同 thread ID 重新进入或恢复未完成执行。

## 10. 使用不透明 Session 实现本地账号认证

### 决策

业务 API 使用用户名和密码登录，签发可撤销的不透明 Bearer Session；健康检查、文档和登录端点保持公开。密码使用 Argon2id，数据库只保存 Session 令牌的 SHA-256 摘要。

### 原因

本地多账号需要区分身份、撤销单个设备、禁用用户并隔离数据。数据库 Session 比自包含 JWT 更便于立即撤销，也不需要引入外部身份服务；FastAPI Security Scheme 仍能在 OpenAPI 中公开认证方式。

### 代价

Session 查询会为每个认证请求增加一次 SQLite 访问；当前仅对邀请码管理强制区分 `admin` 与 `user`，尚未提供细粒度 RBAC 或 OAuth。Bearer 令牌仍不能替代公网场景中的 HTTPS。

## 11. 使用进程内滑动窗口限流

### 决策

登录失败按客户端 IP 与用户名摘要计数；认证后的业务请求按 Session 令牌摘要计数。

### 原因

它能为本地单实例服务提供基本的登录防爆破和误用保护，不引入 Redis 等外部依赖，而且计数键不保存用户名或 Session 原文。

### 代价

计数不跨进程共享，重启后清空。因此 README 明确限制为单实例，不建议通过增加多个 Uvicorn Worker 扩展。

## 12. 通过依赖注入保证离线测试

### 决策

`create_app()` 和 `build_graph()` 接受可选 graph、model、Repository、Checkpointer 和知识库服务。

### 原因

- 单元测试不访问真实 DeepSeek。
- API 测试不需要启动网络服务。
- 每个测试可以使用临时数据库。
- 外部失败、审批和流式事件可以确定性复现。

### 代价

应用装配函数参数较多，但比在测试中修改全局单例更清晰，也降低了测试之间的状态污染。

## 13. 将 Agent 评估与单元测试分开

### 决策

确定性的代码测试由 pytest 和 CI 执行；依赖真实模型行为的 Agent 评估由独立脚本手工运行。

### 原因

真实模型调用可能收费、受网络影响且存在输出波动，不适合作为每次提交的硬性 CI 条件。独立评估仍可跟踪工具选择、回答关键词、延迟和通过率。

### 代价

发布前需要主动运行 Agent 评估，CI 绿色不能单独证明真实模型质量。

## 14. 明确不纳入当前本地多账号版本的范围

当前版本不实现：

- 公共匿名注册、邮箱验证、OAuth、细粒度 RBAC 和跨实例身份服务。

## 15. 使用一次性邀请而不是开放注册

### 决策

注册默认关闭；管理员显式启用后，由一次性高熵邀请码控制注册。首个管理员仍通过本机 CLI 创建，新注册账号由服务端固定为普通用户。

### 原因

- 用户可以自行设置密码，管理员不接触用户密码。
- 不需要立即引入邮件、验证码和机器人治理服务。
- 邀请消费与用户创建可以在同一个 SQLite 写事务中完成。
- 邀请原文只展示一次，数据库只保存摘要。

### 代价

管理员需要安全传递邀请码；当前进程内注册限流不跨实例共享，因此该模式仍面向本地单实例，不等同于可直接公网开放的注册系统。
- PostgreSQL、Redis、消息队列或分布式事务。
- 多实例部署、自动扩缩容和 Kubernetes。
- 云端托管的向量数据库。
- Prometheus、Grafana 或完整分布式追踪。
- 自动同步第三方日历、邮件或任务平台。

这些能力并非不能实现，而是与当前“个人本地使用、公开展示工程能力”的目标不成比例。清晰限制范围也是本项目设计的一部分。
